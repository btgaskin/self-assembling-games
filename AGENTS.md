# Project instructions

This repository studies Barrett's self-assembling games. Use the chapter-level source register and model specifications when changing a game.

- Preserve each model's observations, option sets, feedback recipients, timing, and learning rules. State a deliberate variant in its configuration and documentation.
- Distinguish organism identity, functional module, and game role. Several book models use multiple functional units within one animal.
- Treat source gaps as named questions. Record their resolution and supporting source before introducing a canonical default.
- Keep pretrained module state and adapters explicit. Specify which components learn during each phase.
- Report cumulative, windowed, final-policy, and efficiency measurements by their actual definitions.
- Retain configuration, seeds, source model identifiers, and phase histories with future experimental outputs.
- Write positively and concretely about purpose, mechanism, conditions, and results. Preserve material uncertainty where it affects interpretation or implementation.

Current milestone: reinforcement runtime and mechanism validation. Source-reproduction profiles with unresolved rules stay gated; demonstration choices remain explicit.
